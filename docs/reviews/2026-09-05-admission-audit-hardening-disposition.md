## Compatibility and validation scope

Core 1.1 protobuf, field numbers, hash domains and wire fingerprints remain unchanged. Mining completeness policy advances **3 → 4** and Miningcore settlement policy **4 → 5**, with new semantic/epoch binding and affected effect/summary digests. Accounting wire schema remains 3; settlement-scheme source grammar remains 3. Historical financial contracts require the existing NoLiveDependencies barrier or a distinct scope; these changes cannot reinterpret old liabilities in place.

Local validation covers all 19 Python specification, registry, wire, hash, semantic and regression entrypoints. CI additionally runs protobuf compilation, buf lint/breaking, independent .NET reconstruction, the bounded TLA+ model and all seven realistic mutants on both push and PR paths. Exact CI results are recorded on the PR after completion.

This repository is a protocol specification and executable conformance reference, not the production Miningcore persistence implementation. The arithmetic audit helper assumes accepted, contract-validated source events; matching bundle/chain hashes do not prove authentication, interval completeness or authorized rewards. Those retained proofs are separate mandatory inputs to the normative prune gate. A production integration must still crash-test durable transactions, race staging against admission, exercise PostgreSQL failures, and perform differential payout/recovery tests. Holder retirement and liveness proofs remain explicitly unallocated work, rather than weakened safety conditions.
